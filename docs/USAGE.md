# 使用指南

## 第一次打开

鼠标靠近屏幕顶部的小岛会展开功能面板。左右箭头和底部圆点切换页面；在列表内部滚轮查看更多内容。托盘菜单可打开设置、控制开机启动或退出程序。

设置里的功能显示开关可以隐藏不常用的页面；隐藏页面不等于删除它的数据。

## 邮箱

在「设置 → 邮件」添加完整邮箱地址，选择服务商并填写授权码或 App 专用密码。不要把密码发送到聊天、Issue 或截图里。

| 邮箱 | 获取连接凭据 |
| --- | --- |
| QQ | QQ 邮箱网页版右上角「设置」→「账号与安全」→「安全设置」→「POP3/IMAP/SMTP/Exchange/CardDAV 服务」→开启服务并生成授权码 |
| 163／126 | 邮箱网页版「设置」→「POP3/SMTP/IMAP」→开启 IMAP，并按页面验证生成客户端授权密码 |
| 腾讯企业邮 | 网页版设置中的客户端收发设置；企业管理员可能限制 IMAP 或第三方客户端 |
| iCloud | Apple 账号开启双重认证后，在账号安全页面生成 App 专用密码 |
| Gmail | Google 账号开启两步验证后生成应用专用密码；单位账号可能由管理员禁用此入口 |

以服务商当前页面为准，岛仔设置页也提供对应说明和网页入口。Gmail 在部分网络环境下需要能够访问 Google；岛仔不会替你改变系统网络设置。

Outlook、Hotmail、Live 和 Microsoft 365 云邮箱需要 OAuth 授权，目前暂不支持。设置页明确标注支持状态；填写微软个人邮箱地址或已知的微软云 IMAP 主机时，会提示并停用测试及保存按钮。

连接后读取最近 20 封邮件；运行期间列表最多保留 60 封。新邮件优先通过 IMAP IDLE 接收，并有定期防漏检查；服务器、网络及服务商投递耗时仍会影响实际到达时间。

验证码卡片显示来源与主题，点击即可复制。点邮件列表进入详情，滚轮查看正文；「阅读全文」打开独立阅读窗口。正文内的网页链接交给默认浏览器打开。

HTML 邮件保留标题、列表、加粗、引用和表格的阅读结构。图片显示有意义的替代文字，不自动加载远程图片；正文支持选择复制。

邮件列表可切换「全部／未读」。打开邮件后会标为已读，也可在邮件行、详情或全文窗口手动切换已读状态。删除会移到当前模式的回收站；点击列表右下角的垃圾桶图标进入回收站，可将邮件恢复到收件箱。「设置 → 邮件 → 同步邮件操作到邮箱」默认关闭，仅在本机保存整理状态，不改动真实邮箱；开启后已读、删除和恢复同步服务器，失败时保留列表记录并提示。远程删除和恢复要求邮箱支持 IMAP MOVE。仅提供 UIDPLUS 的邮箱可使用本机回收站。切换开关不会补交之前的本机操作。

列表和筛选数量对应当前加载的最近邮件；仅本机模式下「全部已读」只处理当前加载的记录；开启同步后会处理已连接邮箱的全部未读邮件，不限于列表记录。常规状态刷新只读取最近邮件标记，正文优先复用内存缓存。

## 日程

在「设置 → 日程」选择平台，填写平台提供的 CalDAV 连接信息。只登录或安装飞书、钉钉、企业微信桌面客户端，不会自动授予岛仔日历读取权限。

- 左侧月历选择日期；右侧按时间显示日程，全天安排在前。
- 大卡片显示选中的日程；滚轮只滚动下方列表，点击其他条目切换大卡片。
- 跨天日程会出现在覆盖的日期中。结束时刻按日历提供的数据展示。
- 自动同步默认每 5 分钟进行；点击右上角更新时间可手动刷新月份。
- 提前提醒时间可在设置中选择 5／15／30 分钟；全天安排展示在日历中，不在午夜弹出会议提醒。
- 普通邮件正文中的日期不会加入日程；带日历附件的正式邀请会自动显示。
- 邮件日程右侧的 × 可忽略该日程，停止显示与提醒；在邮件详情或全文窗口选择「恢复日程」可恢复。忽略邮件来源不会删除工作日历中的对应安排。

**当前边界：** 邮件日程依赖当前加载的邮件记录，不是完整邮箱归档；复杂的批量重复规则修改可能提示不支持。日历同步失败会显示错误，不能把“已连接”当成所有日程都已成功同步。程序退出、电脑关机或睡眠期间无法持续接收提醒。

## 课表（不止课表 NOS）

在「设置 → 课表与多端 · 课表」填写「不止课表」Web 端地址与访问令牌，岛仔就能把课表读进来，显示在**日程页**和**常驻栏**。NOS Web 端始终是一个**独立服务**：既可以连接已经部署好的服务器，也可以让岛仔直接在本机把它启动、停止或重启。

- **日程页**：课程、会议、期末考试、课间休息与飞书／钉钉／邮件／本机日程混排在同一份月历与列表里，左侧月历上的圆点也会标出有安排的日子。课间休息由 NOS 按当天相邻两节课之间的空档补出来，标灰色 `NOS · 课间`，只占列表、不抢上方主卡片。
- **待办页**：「不止课表」里的待办以只读方式混进待办清单，右侧标 `NOS`、悬停显示截止时刻；不能勾选、编辑或删除，要改请到 NOS 里操作。设置页「待办」里同样能看到这些条目（也只读）。本机待办仍照常增删改，两份数据互不影响。NOS 待办不额外提醒，避免和 NOS 自己的提醒重复。NOS 会议保持在日程页，不进待办页。
- **常驻栏**：在「设置 → 状态组件」里打开「下一节课」，收起时岛体上会显示下一节课的开始时刻与课名（例如 `08:00 信号与系统`）；正在课间时改显示还剩几分钟（例如 `课间 8′`），上课后再回到下一节课。没有课表数据时这一格自动隐藏。
- **设置页**：「设置 → 课表与多端 · 课表」下方会列出今天的课程，方便确认拉到的数据对不对；点「保存并测试连接」会立刻校验地址与令牌。

### 配置步骤

1. 在「不止课表」的服务器上设置访问令牌：编辑 `/etc/nos/nos.env` 写入 `NOS_API_TOKEN=<随机长串>`，然后 `sudo systemctl restart nos`。部署脚本会在令牌文件不存在时自动生成并打印一次。
2. 在岛仔「设置 → 课表与多端 · 课表」填服务器地址（到站点根即可，例如 `http://192.168.1.10:8000`）与同一个令牌，点「保存并测试连接」。
3. 令牌只保存在 Windows 凭据管理器里，不写入配置文件；「忘记令牌」可清除。

### 让岛仔控制本机 NOS Web 服务

在「设置 → 课表与多端 · 课表 → NOS Web 服务」打开「由岛仔管理本机服务」，岛仔会把 NOS 的 Web 端作为**独立进程**（uvicorn）拉起，不会把它的代码或数据模型搬进岛仔：

1. **Web 目录**可以留空：点「启动」时会自动从程序目录／当前目录向上几级探测 NOS 的 `web` 目录（本机 `E:/dev/NOS/web` 可命中），也可以手填或点「自动探测」。
2. **Python** 留空即可：优先用 `web/venv`，找不到再用 PATH 上的 python；也可以手填解释器绝对路径。依赖按 `web/requirements.txt` 安装。
3. 默认监听 `127.0.0.1:8000`，只对本机开放。改端口后岛仔会自动把「服务器地址」对齐到新地址；改成 `0.0.0.0` 会把服务暴露到局域网，请先确认令牌与网络环境。
4. 直接回顶部点「启动」。令牌留空时岛仔会自动生成 32 字节随机令牌并写入 Windows 凭据管理器，同一份令牌注入服务进程作 `NOS_API_TOKEN`，服务端与客户端天然对齐，不用手工编随机串也不用改 systemd 配置。想指定自己的令牌，才需要在「连接」里填好并点「保存令牌」。服务还没起来时点「保存并测试连接」会报连接失败，属正常。启动的成功、失败与日志路径会直接显示在服务卡片里，不再只靠一闪而过的气泡。
5. 服务就绪后岛仔自动开始同步课表；「重启」用于让目录、端口或令牌的修改生效，「停止」结束整个进程树，「打开 Web」用默认浏览器打开周表页面，「查看日志」打开 `%APPDATA%\Daozai\nos-web.log`。

状态栏每几秒刷新一次，会区分「运行中」（本次由岛仔拉起）、「外部运行」（端口上跑着别的实例或上次会话遗留）、「异常」（端口通但接口不可用，例如令牌不匹配或版本过旧）。端口已被占用时岛仔不会重复拉起第二个实例。

打开「随岛仔启动自动运行」后，每次启动岛仔都会自动拉起服务；退出岛仔时进程由 Windows 作业对象一并收走，不会留下占着端口的后台 Python。若上次异常退出留下进程，PID 记录在 `%APPDATA%\Daozai\nos-server.pid`，点「停止」可以按这份记录清理。

**当前边界：** 令牌由服务端强制校验，服务器未配置令牌时接口一律拒绝（返回「服务器未配置访问令牌」）。课表每 5 分钟自动刷新一次；拉取失败时保留上一次成功的数据，界面上显示错误原因。课表里的时间按**岛仔所在电脑的本地时区**解释，与服务器时区无关。「不止课表」的鸿蒙／Android／iOS 端各自存本地数据、彼此不同步，因此岛仔读到的是 **Web 端那份**课表。跨公网访问请给服务器配 HTTPS。本地服务模式只在 Windows 上随岛仔退出自动回收进程；日志超过 2 MB 会滚动为 `nos-web.previous.log`。

## 多端同步（两台 Windows）

岛仔默认完全本地；在「设置 → 课表与多端 · 多端同步」接入同一个 NOS 后，两台 Windows 上的岛仔可以共用待办、饮水、番茄、本机日程与账号级设置。

1. 在 NOS 里为岛仔建一枚令牌，勾选 `sync:read`、`sync:write`、`presence:write`（只读课表的 `agenda:read` 令牌不能同步）。
2. 「设置 → 课表与多端 · 多端同步」填地址、粘贴令牌，点「保存并测试连接」。课表和多端同步共用同一个 NOS 地址与一枚令牌（勾选「读取日程 + 多机同步」），在任一分段保存都会同时写入两个凭据条目。
3. 「设置 → 课表与多端 · 多端同步 → 所有设备」给本机起名（如「书房台式」）；设备列表会显示在线状态与最后活跃时间，可指定一台**主设备**负责弹待办与日程提醒。
4. 第二台机器用同一账号的令牌接入；首轮以先接入的设备为准，另一台采纳服务端数据，本地旧文件备份为 `*.pre-sync.bak`。

**同步范围**：待办、饮水、番茄、本机日程、账号级设置（皮肤、专注/饮水时长、页面顺序等）。
**不同步**：窗口位置与大小、显示器、置物架路径、通知监听、邮件与网盘凭据。课表本来就在 NOS，两台各自读同一份，不重复同步。

待办同步的几条行为：

- `todo.txt` 格式不变，稳定 id 记在同目录的 `todo-ids.json` 里；外部手改 `todo.txt` 也能靠内容比对找回原来的条目。
- 首次接入会先拉服务端、再上传本地，避免第二台把同一批待办重复创建一遍。
- 两边同时改同一条时以服务端为准，本地版本写进 `sync-conflicts-日期.txt`，不会静默丢。
- 正在输入或编辑待办时暂不应用远端变化，提交后 500ms 内继续对账。

饮水同步的几条行为：

- 每一口都作为一条记录同步，两台的总量按记录求和；在 A 喝 250 ml，B 的进度环与柱状图会一起涨。
- 撤销只影响最近一条；如果远端刚好也在加量，两边最终总量仍等于「各自喝掉的和」。
- 首次接入时服务端已有饮水记录就直接采纳，不会把本地旧总量再加一遍；服务端为空才把本机 `hours[24]` 迁移过去，柱状图保留。
- 目标、杯子容量与提醒时段属于账号级设置，等设置同步接入后再跨机一致。

番茄同步的几条行为：

- 一台开始专注，另一台会显示同一个倒计时并停下自己的计时；**只有开始的那台响铃**，另一台安静跟随。
- 两台同时开始，服务端只保留最后一条 `running`，另一条自动标成 `superseded`，不会两边一起响。
- 在另一台上按「开始」就是接管：剩余时间变成这台的新会话，原设备随即停止。
- 计时按截止时刻计算，合盖睡眠或卡顿后醒来会直接补算真实流逝时间，不会少走；完成记录保存在本机 `focus-history.json`，最近 400 条。

本机日程与设置：

- 本机日程按 `uid` 合并：两台各自新建的日程都会出现，编辑与删除也会同步；提醒时间随日程一起走，远程改动后会重新挂提醒。
- 账号级设置按 38 个白名单键逐项同步：皮肤、主题、极简、时钟制式、页面顺序、通知声音、专注/饮水时长、天气城市等。窗口位置、显示器、置物架路径、通知监听、邮件账号与凭据**不会**上传。
- 第一次接入时，服务端已有的键会先采纳；服务端没有的键才上传本地值。极简模式与设置页一样会联动关掉吉祥物。

令牌只进 Windows 凭据管理器；公网访问请用 HTTPS。当前版本已接通待办、饮水、番茄、本机日程、账号级设置，以及下面的「异地天气」和「异地监控」；本地模式不产生任何同步请求，也不会生成 `device.json`。

### 异地天气（每台看自己的城市）

- 天气城市、定位和城市列表**不再跨机同步**：每台岛仔显示自己所在地的天气，互不覆盖。
- 每台设备通过在场心跳（约 30 秒一次）把本机城市、温度和天气状况带给其他设备，只显示 90 秒内在线的设备。
- 天气页点地点名打开的城市面板底部有「异地天气」一行，例如「宿舍笔记本 · 上海 22°」；「设置 → 天气 → 异地天气」有完整卡片，两台同城时自动隐藏，避免重复。
- 岛上的天气胶囊仍只显示本机城市。

## 常驻栏状态组件

「设置 → 页面管理 → 状态组件」里的开关决定岛体**收起时**显示哪些内容：电量、岛上歌词、网速、下一节课、AI 余额、进行中日程、CPU 信息、GPU 信息、内存信息、硬盘信息、温度。每项都独立，关掉后不再在常驻栏占位，相关功能页仍正常工作。温度默认开启，有热区或显卡读数时会直接显示在收起的岛上。

- **AI 余额**：显示已「常驻岛上」的账号额度环（余额数字或剩余点数）。关掉后「AI 额度」页照常更新，只是不在岛上显示；账号是否常驻仍在「设置 → AI 额度」里逐个控制。
- **进行中日程**：显示当前正在进行的日程标题（例如 `进行中 · 组会`）。日历、邮件邀请、本机日程和课表四类来源都参与；全天事件、已结束和尚未开始的日程不显示，没有进行中的日程时这一格自动消失。
- **硬件占用**：CPU、GPU、内存和硬盘分别显示实时占用率（例如 `CPU 42%`）。系统没有提供对应读数时该格自动隐藏，不影响其他组件。

固定排在常驻栏末尾的组件依次是网速 → 下一节课 → 进行中日程 → CPU → GPU → 内存 → 硬盘 → 温度，与设置页列表顺序一致，不参与拖动排序；有数据时才占位，没有时自动收起。设置页「常驻排列」预览也按这一顺序显示，已开启但暂无数据的组件以灰色占位。

## 音乐、专注、饮水与待办

音乐来自 Windows 媒体会话，播放器需要提供系统媒体信息。歌词匹配依赖歌曲元数据和外部服务，个别版本、纯音乐或未找到歌词的歌曲可能无法显示同步歌词。

**WebDAV 曲库**：可以在「设置 → 音乐与歌词 → WebDAV 音乐」连接自己的 WebDAV 服务器，直接在岛仔里播放上面的音乐。填好服务器地址（例如 `https://nas.example.com/music`）、用户名和密码，点「测试连接」；成功后下方会出现曲库，点文件夹进入、点歌曲播放，播放条支持上一首／播放暂停／下一首、拖动进度和音量。

**由「不止课表」统一管理（推荐）**：如果已连接 NOS，可跳过上面的手填——登录 NOS Web，到「我的 → WebDAV 音乐」填一次地址、账号与密码，岛仔连接课表后会自动获取，设置页这三项变为只读，不再需要在每台机器上输入。改配置后到设置页点「从 NOS 重新获取」即可；服务端把密码加密保存，下发后仍落到本机凭据管理器。未配置 NOS 时保持原来的本机手填方式，两种方式互不影响。

**岛仔音乐页**：无系统媒体时，标题区显示 WebDAV 的连接状态与曲目数，中间的播放键直接起播。标题行右侧的曲库胶囊（显示曲目数）可展开曲库面板：看连接地址、点任意曲目播放、切换「顺序 / 乱序」。播放列表默认就是当前曲库目录里的音频，**不需要先逐首加入序列**；如果你在设置页用「＋序列」编了自己的顺序，则优先播序列（清空后退回目录）。目录与顺序都会缓存（`webdav-dir.json` / `webdav-queue.json`），重启岛仔后立刻有歌单；切歌和播完自动续播都遵循当前顺序，乱序不会连播同一首。

只支持 **https**（本机回环地址可用 http），地址里不能带账号密码；密码保存在 Windows 凭据管理器，`webdav.json` 只记地址、用户名、当前目录与是否由 NOS 托管。

**跨设备播放**：开启多机同步后，每台岛仔把「在放什么、放到哪」上报 NOS（约 2 秒一次，只传曲名/歌手/进度，不传文件内容），同一时间只有一台真正出声。别的设备在放时，本机音乐页直接显示「书房台式 正在播放 · 晴天 01:12 / 04:29」，中间播放键变成「接手」：

- 点接手 = 向 NOS 抢占播放权（epoch +1），对方在 2 秒内暂停；
- 对方放的是 WebDAV 曲目时，本机从它停下的进度继续播；
- 对方放的是系统播放器（QQ 音乐等）时，只抢播放权、不接管那一首，因为拿不到可续播的地址；
- 被接手的机器不会自动抢回来，要等你在它上面重新点播放。

网页端登录后，首页顶部会出现「谁在播放」条：设备名、曲名、实时进度，5 秒刷新，没人播时自动隐藏。支持 MP3、FLAC、WAV、OGG 与 M4A／AAC；播放前会整首下载到系统临时目录再解码，所以第一次播放会有下载进度，切歌时会清掉上一首的缓存。WebDAV 播放是独立于系统媒体会话的通道：岛仔自己出声时，岛上的封面、歌词与系统媒体控制仍对应原来的播放器。

专注与休息需点击开始，结束后可进入下一阶段。饮水可设置目标、单次量、提醒间隔和时段；记录错误可以撤销。待办提醒是可选项，填写任务后通过日期／时间选择器设置，不需要手写时间格式。

**在设置页里改待办**：「设置 → 待办与置物 → 待办」是同一份清单的另一个视图，不用先跳回岛上也能改：左侧勾选框标记完成，正文点一下就能就地编辑（回车或点别处保存，留空视为放弃），顶部输入框回车添加，右侧「提醒」打开时间与每周重复，末尾 `×` 删除。改动立刻写回 `todo.txt`，岛内待办页同步生效。「不止课表」的待办在这里同样只读展示。岛内待办页仍是紧凑的一屏三行视图，适合日常勾选。

## AI 额度

先登录相应工具，再在岛仔 AI 额度设置中识别本机账号。多个账号可分别命名、选择配色并决定是否常驻。Codex、Claude、Kimi 的登录由各自客户端管理。Claude 桌面端只读本机历史和用量缓存，切换账号后需等待新记录。手动启用 Claude Code 本地采集时，岛仔会写入采集脚本并设置状态栏，已有其他状态栏命令时保留原配置。

Grok Bot、Gemini、豆包提供各自的连接入口；会话过期时重新连接。豆包读取网页会员的 5 小时、每周及活动额度：点击「浏览器登录」，优先使用系统默认的 Chrome／Edge，在独立窗口完成官网登录，无需浏览器扩展；默认浏览器不支持时使用已安装的 Chrome／Edge。也可点击「从本机导入」读取豆包客户端当前账号，或手动提供 Cookie。本机登录缓存被客户端占用时，请使用浏览器登录。登录状态加密保存在本机。额度接口、订阅类型和服务商策略可能变化，未识别或请求失败时应以对应服务的官方页面为准。

### 什么时候回血

额度窗口的重置时刻（例如「今天 23:00 重置」）会出现在三个地方：

- **额度页**每个窗口下面直接写着，点开就能看到。
- **常驻栏的额度环悬停**会多显示一行重置时刻；这项不需要设置。
- **常驻栏环右侧的琥珀色时刻**：只在「剩余 ≤15% 且 12 小时内会重置」时出现，显示的就是回血时刻（同一个窗口其余时间不占位）。时刻比顶栏时钟小一号，别当成两个时钟。
- **重置后提醒一次**（默认开，在「设置 → AI 额度」里可关）：窗口到点翻页、而且重置前确实快用完（≤15%）时，岛仔提示一句「额度已重置 · 现在剩余 100%」，点提醒回到额度页。因为额度每 3 分钟刷新一次，这条提示最多晚 3 分钟；从没动过的额度窗口翻页不会提醒，避免每 5 小时吵一次。

这些时刻都来自服务商返回的绝对时间，5 小时这类滚动窗口会随使用时段前后移动，所以按「几点重置」显示比写死日程更准。服务商没给重置时间时，岛仔如实显示「重置时间未知」，不会编造。

**WorkBuddy 积分是个例外**：它的额度接口（`get-user-resource-summary`）只返回余量（套餐 / 赠送各剩多少），**不返回周期**，所以这里给不出确切时刻，只能按官方规则说明——体验版套餐积分每月 1 日 00:00 重置、当月有效不结转，赠送积分自到账起 1 个月内有效；付费版套餐按购买日顺延一个月。鼠标停在岛上的 WorkBuddy 图标上能看到完整积分、资源包明细和这条规则，设置页卡片里也写着同一句。等哪天接口带上周期字段，这里会直接显示具体时刻。

### 手动记一笔「限流到点」

WorkBuddy 还有一层查不到的额度：**模型免费额度的限频**。它只在界面上出现一次——「您使用 Hy4 flash 模型的免费额度已超出频率限制，可在 2026-11-17 23:43:31 重置后继续使用」——接口不返回、也算不出来，所以岛仔不去猜，改成「看到就记一笔，到点叫一声」。

- **入口**：额度页 WorkBuddy 卡片右侧的「记录限流」，或「设置 → AI 额度」里每个账号行的「记录限流」。
- **填什么**：模型名可以留空；恢复时刻只填 `23:43:31` 就按今天算，今天这个点已经过了会顺延到明天（小窗里当场显示折算结果），带日期写 `2026-11-17 23:43:31` 就按那天算。刚复制过提示原文的话，打开小窗时会自动从剪贴板里把时间捞出来填好。
- **记下之后**：卡片最后一行变成「Hy4 flash 限流中 · 23:43 恢复 · 还有 1 小时 22 分」，按钮变成「改时间」。
- **到点**：岛仔提醒一次「额度限流已到时间 · 现在可以正常使用了」，跟其它提醒一样同时发系统通知；半小时后这条记录自己退场，卡片恢复显示积分构成。同一个账号同一个模型只留最新一条，改时间就是覆盖。

记录存在 `%APPDATA%\Daozai\quota-limits.json`，退出重开仍在；「清除记录」可以随时删掉。

## 系统监控

装上就有一个「系统监控」功能页面，在岛上左右翻页即可到达；页面和后台采集默认都开着。也可以到「设置 → 页面管理」调整它的顺序或关掉。

### 监控页

一页放下三块信息：

- **左侧**：CPU 当前占用（大号数字）、负载高低、实时频率、温度与计算机名。
- **右侧 2×2 + 电源条**：内存（占用率与已用/总量）、GPU（占用率与温度·功耗）、硬盘（占用率与读写速度）、网速（下行/上行）；下方电源条显示交流接入、电池百分比、剩余电量、充/放电功率与可读到的交流输入功率。
- **底部**：最近约 12 分钟里均匀取样的六列趋势，每列显示时刻与两项读数，下方是对应的双折线。右侧「负载 / 网络」切换那两行数据看哪一组。

右上角「刷新」清空曲线、重新开始一个采样窗口。系统没提供对应计数器时该项显示 `--` 而不是 0。温度分两条通道：有 ACPI 热区时读热区（桌面主板通常一个都没有），没有热区时退回显卡温度并标上 `GPU ` 前缀；两条都读不到才显示 `--`。显卡温度/功耗/功耗上限/风扇/显存来自 NVML（`nvml.dll`，随 NVIDIA 驱动安装，普通权限即可，与任务管理器 GPU 页显示的是同一份驱动数据）；没有 NVIDIA 卡时 GPU 那几项保持 `--`。电源数据来自 WinRT 电池报告与 Windows Power Meter；系统不提供充电功率或交流功率时显示 `--`，放电功率由剩余电量变化推算。

### 异地监控（可选）

「设置 → 系统监控 → 显示」里有一个「查看其他设备的系统监控」开关，默认关闭。打开后：

- 监控页左上角出现「异地 N」按钮，点开一个独立的「异地监控」窗口；
- 窗口里列出所有在线设备通过在场心跳带来的 CPU、内存、硬盘、温度、显卡占用率（纯数字，约 30 秒刷新一次）；
- 「设置 → 系统监控 → 其他设备」也有一份卡片摘要；
- 不上传进程名或窗口标题等隐私信息，关闭开关后界面不再显示（本机仍在心跳里上报，其他端同样受它们自己的开关控制）。

### 深度传感器（可选提权）

「设置 → 系统监控」底部有一个「深度传感器」开关，默认关闭。它做的事只有一件：用一次管理员授权再起一个
**独立的助手进程**（`daozai.exe --elevated-sensors <父进程 PID>`），由助手去读 `MSAcpi_ThermalZoneTemperature`
——某些笔记本机型只有提权后才返回热区。助手每 5 秒把读数写进 `%APPDATA%\Daozai\elevated-sensors.json`，
主体只读文件；文件超过 20 秒没更新就视为失效，助手退出后不会残留陈旧温度。助手发现父进程结束会自动退出并删掉该文件。

关掉开关时岛仔完全不申请提权，仍只读用户态 API。桌面平台（无 ACPI 热区）打开这个开关通常也读不到东西，
界面会显示「助手运行中，热区读数已并入温度」但温度不会变化 —— 这是硬件没暴露热区，不是开关坏了。
重启岛仔后助手不会自动再拉起，设置页会显示「助手未运行」并给出「重新授权」按钮。

### 能读到哪些传感器

显卡温度/功耗/风扇来自 NVML（零提权），温度优先用 ACPI 热区、没有再退回显卡温度；磁盘温度和 CPU 温度目前**没有接入**，
原因、实测数据与后续可选方案都记在 [sensors.md](sensors.md) 里，动手前先看那份文档，避免重复蹚走不通的路。

### 常驻栏与独立窗口

- **常驻栏网速**：设置 → 系统监控 →「常驻栏显示网速」。收起时岛上直接显示 `↓下行 ↑上行`，固定排在常驻栏最末尾，不参与拖动排序。
- **独立仪表盘**：设置 → 系统监控 →「显示监控窗口」，或托盘菜单「显示监控窗口」。780×452 的深色卡片，信息比监控页更完整，按住任意位置可拖动；右上角齿轮可以切换窗口置顶、鼠标穿透、贴靠右下角，也能关闭窗口。

### 设置与数据

「设置 → 系统监控」顶部是一张实况卡：左侧是本机 CPU 占用与负载状态、实时频率和温度，底部一行是网速、内存、GPU、磁盘的当前值，右下角显示更新时间，圆形按钮用来重启采集服务（不会清空曲线）。

采样间隔默认 1000 毫秒，可调整为 250–60000 毫秒；间隔过大会平滑掉瞬时峰值。网卡默认统计全部已连接网卡，也可只选一块；切换网卡会重置速率基准，切换瞬间不会出现假尖峰。

阈值提醒可分别设置今日流量、CPU 占用和内存占用，填 0 表示关闭。越限时弹出托盘气泡，同一条提醒在冷却时间内不重复。

「设置 → 流量历史」显示今日、近 7 天、近 30 天汇总，最近 14 天柱状图和最近 30 天明细，按日归档最多保留 400 天。页面打开时读取一次；运行期间有新数据时点「刷新」重新读取。

配置与历史保存在 `%APPDATA%\Daozai` 下的 `monitor.json` 与 `monitor-history.json`；诊断记录每 30 秒覆盖写入 `diagnostics\monitor.log`。

**当前边界：** CPU 副标题显示实时频率而不是温度——温度需要额外驱动或管理员权限，本程序不读。GPU 占用取自各引擎实例的最大值，与任务管理器的整体 GPU 口径不完全一致；磁盘占用按全部物理磁盘汇总。趋势只保留本次运行的数据，重启岛仔后重新累积。关掉监控页且没有开启常驻栏网速与独立窗口时，采集会一起停止。窗口置顶与穿透是会话内状态，重启后恢复默认（置顶开、穿透关）。

## 更新、卸载与数据目录

双击新版 `Daozai-Setup-v版本号-x64.exe`，可通过路径输入框或「浏览…」选择安装文件夹，勾选「创建桌面快捷方式」和「开机自启」，再点击「一键安装」。首次安装默认创建桌面快捷方式、不开机自启；升级默认保留现有选择。安装位置默认为 `%LOCALAPPDATA%\Programs\Daozai`，可改为其他有写入权限的文件夹，用户数据仍保存在 `%APPDATA%\Daozai`。

升级安装保留数据。若提示岛仔正在运行，先从托盘退出，再点击重试。

在 Windows 已安装应用中卸载会移除程序和快捷方式，但保留数据。若要清除账号，先在岛仔设置中移除对应连接，避免只删配置文件而留下系统凭据。

## 常见问题

**窗口没有出现：** 检查托盘是否已有实例、是否在全屏应用中、设置是否启用了全屏隐藏。

**邮箱登录失败：** 确认填的是授权码／App 专用密码、IMAP 已启用、账号没有被管理员限制。

**日程连接成功但没有安排：** 手动同步所选月份，确认平台授权的日历包含该日程；出现错误时保留错误文字即可，不要提供密码。

**验证码没有马上出现：** 确认邮件是否已到达收件箱，而非垃圾箱；检查岛仔是否运行、连接是否正常。

**网速或占用没有数值：** 确认「设置 → 系统监控」里的显示开关已打开，且「启用系统监控」没有被关闭。全部为空时检查 `%APPDATA%\Daozai\diagnostics\monitor.log` 是否在更新；单项显示 `--` 表示系统没有暴露对应计数器，不影响其他指标。

**图标或布局异常：** 反馈 Windows 版本、屏幕缩放比例、显示器数量和截图。截图先遮挡账号、验证码及私人日程。
